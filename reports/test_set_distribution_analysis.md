# Test Set Distribution Analysis
Analysis of `dataset/test_set.csv` relative to the current merged training corpus (`dataset/processed/merged_retraining_corpus.csv`).
Generated by `reports/_analyze_test_set_distribution.py`.
---
## 1. Where was this dataset created from?
`dataset/test_set.csv` is produced by **`dataset/labeled_corpus.py`** via `build_test_dataframe()` → `write_csvs()`. It is a **held-out curated corpus** built from deterministic templates in `_test_templates()`, expanded across **11 domain slots** (science, technology, education, medicine, politics, philosophy, legal reasoning, public debate, social media discourse, news analysis, daily life).
The companion file `dataset/master_dataset.csv` uses **different** `_master_templates()` so training and test phrasing stay disjoint by design. `dataset_generator.py` and `classification/retrain_merged.py` explicitly **exclude** any row whose text appears in `test_set.csv` to prevent leakage.
Every row carries `reviewer_notes = "test seed v1"`, matching the `corpus_id="test"` tag in `labeled_corpus.py`.

**On-disk composition (n=200):** **88** rows from `_test_templates()` (`test seed v1`) and **112** rows from deterministic padding (`test augmentation`) in `_materialize()` when an older 8-template build undershot the 200-row target. Padding rows use hash-picked labels and share a repetitive meta-vocabulary (`synthetic vignette`, `evaluation bookkeeping`).

## 3. Manual or automatic annotation?
**Automatically generated**, not manually annotated from external corpora.

- Rows are instantiated from fixed English templates with domain placeholders.
- Labels are assigned **deterministically by template** (each template hard-codes a pramāṇa and strength).
- `review_status = approved` reflects pipeline bookkeeping, not independent human review.
- This contrasts with `aaec_reviewed_dataset.csv` and `ibm_reviewed_dataset.csv`, which come from manual Nyāya annotation of argumentative essays and IBM ArgKP claims.

## 8. Conclusion: in-distribution or out-of-distribution?
**`test_set.csv` is out-of-distribution (OOD) relative to the current merged training corpus**, despite sharing the same four Nyāya labels and zero exact-text leakage.

### Evidence for OOD

- **Lexical shift:** Jensen–Shannon divergence vs merged training is **0.507**, indicating a measurably different word-frequency profile.
- **Length mismatch:** Test sentences average **15.8** words vs **19.5** in training (3.7 word gap).
- **Class skew:** Test set is roughly balanced (~23–29% per class), while merged training is **~80% Anumana** — total variation distance **0.58**.
- **Padding artefact:** 112/200 rows are generic `test augmentation` fillers with hash-assigned labels, further diverging from natural argumentative training text.
- **Genre / provenance:** Test text is **synthetic template prose** with domain parentheticals; training is dominated by **argumentative essays (AAEC)** and **claim pairs (IBM)**, plus older synthetic nyaya rows.
- **Vocabulary:** Test-frequent tokens (`telemetry`, `bench`, `metaphors`, `filings`) differ from training-frequent argumentative tokens (`argument`, `claim`, `therefore`, `because`).

### What is still aligned

- Same label schema and cue families (perception, inference, analogy, testimony).
- Deliberately **balanced** pramāṇa counts for evaluation (unlike training).
- **No duplicate texts** with nyaya, AAEC, or IBM reviewed sets.

### Practical implication

Held-out accuracy on `test_set.csv` (~68–76% in project reports) **understates in-corpus performance** and **overstates real-world generalization** to AAEC/IBM-style arguments. The test set is best interpreted as a **curated, leakage-free sanity check** on template-style English, not as i.i.d. draws from the merged training distribution. For deployment claims, evaluate on manually reviewed AAEC/IBM holdouts or fresh human-annotated samples from the target domain.
