# Train / Validation / Test Split Documentation

How InferAI partitions data for training and evaluation. Canonical merged size **1861**. Generated by `reports/generate_professor_documentation.py`.

## Overview

| Split | Rows | Fraction | Source |
|-------|-----:|----------|--------|
| Train | 1488 | 80% | `merged_retraining_corpus.csv` |
| Validation | 373 | 20% | `merged_retraining_corpus.csv` |
| Held-out test | 200 | — | `dataset/test_set.csv` (separate file) |

## Train split

Created by `sklearn.model_selection.train_test_split` with `test_size=0.2` and `random_state=42`. **1488** rows from the merged retraining corpus (n = 1861) are used for classifier fitting.

## Validation split

The remaining **373** rows (20%) form a random holdout used for in-training evaluation (`reports/final_retraining_report.md`).

## Held-out split

`dataset/test_set.csv` contains **200** rows built by `dataset/labeled_corpus.py`. It is never concatenated into the merged training corpus.

## Random seed

- **Train/validation partition:** `random_state=42`
- **Merge shuffle:** `random_state=42` in `classification/retrain_merged.py`

## Why leakage cannot occur

1. **Text-level exclusion** of `test_set.csv` rows before merge.
2. **Separate held-out file** loaded only at evaluation.
3. **Zero exact-text overlap** with AAEC/IBM reviewed sources (`reports/test_set_distribution_analysis.md`).
4. **Exact duplicate audit:** 0 cross-split exact duplicates (`reports/data_leakage_report.md`).
